---

# 1. Overview

The Email Service is responsible for all transactional emails generated by the DigiIndia Student Innovation Platform.

It provides a centralized communication layer between backend services and users.

The service uses the official **Brevo Email API (REST API)**.

SMTP is **not** used in the DigiIndia backend architecture.

---

# 2. Important Note

## Brevo API is NOT SMTP

DigiIndia integrates with Brevo using the official REST API.

Every email request is sent as an authenticated HTTPS request to Brevo's Email API.

SMTP Relay is intentionally **not used**.

Reasons

• REST APIs are easier to integrate with Python.

• Better authentication.

• Better analytics.

• Template management.

• Delivery tracking.

• Bounce tracking.

• Webhooks.

• Easier retries.

• Consistent architecture.

Since every external service already communicates through REST APIs

Gemini API

↓

Grok API

↓

NVIDIA API

↓

Cloudinary API

↓

Brevo Email API

the backend follows one unified communication pattern.

# 35. Conclusion

The Email Service provides a centralized, secure, and scalable communication layer for the DigiIndia Student Innovation Platform.

All transactional emails are delivered through the official **Brevo Email API (REST)** using authenticated HTTPS requests.

The architecture intentionally avoids SMTP in favor of REST APIs to maintain consistency with other integrated services such as Gemini, Grok, NVIDIA, Cloudinary, and Firebase, resulting in a unified, maintainable, and production-ready backend.
